# FitMate — AI Coach / Program Plans / Subscriptions Roadmap

> Master roadmap for the "FitMate Implementation Specification" PDF, split into separately executable
> plans. Each numbered plan file in this directory produces working, testable software on its own.
> Execute plans in order — later plans consume contracts defined by earlier ones.

**Priority order (per Damian):** Program Plans first ("depending on the day I should know what to
train"), then the program builder made of workout templates, then everything else in the spec.

## Key design decisions (locked)

### D1 — Fixed-length AND open-ended ("keeps going") programs
The spec models `ProgramPlan.StartDate`/`EndDate` as required. Damian wants "X weeks **or** one that
keeps going". Decision: **`EndDate` is nullable.**

- `EndDate != null` → fixed-length plan. All `ProgramPlanDay` rows generated at activation. Progress
  shows completion %, adherence %, streak.
- `EndDate == null` → open-ended plan (FixedWeekdays or Rotation only; CustomCalendar requires an end
  date). Days are generated for a **rolling 28-day horizon** at activation and topped up whenever the
  today/calendar endpoints run for that user (request-boundary maintenance per spec §66 first version;
  Plan 11 moves this to a job). Progress omits completion % (no denominator) and shows adherence %,
  streak, completed count.
- Determinism is preserved either way: the home page always reads persisted `ProgramPlanDay` rows —
  never asks AI, never computes on the fly (spec §2.5).
- Entitlement `ProgramPlanDurationMonths` (Plan 04) applies only to fixed-length plans; open-ended
  plans are gated by a separate boolean entitlement decision later — until Plan 04 lands, open-ended
  is available to everyone.

### D2 — "Today" and time zones
`ScheduledDate` is `DateOnly`. The client sends its **local date** as a query parameter
(`?date=2026-08-05`) to the today/calendar endpoints; server falls back to `DateOnly.FromDateTime(DateTime.UtcNow)`
when absent. Missed-day marking uses the same reference date and only marks days **strictly before** it.

### D3 — One active plan rule now, entitlement-driven later
Plan 01 enforces max **one active plan per user** as a hard rule inside `ProgramPlanService.ActivateAsync`.
Plan 04 replaces the constant `1` with `IEntitlementService` lookup (`ActiveProgramPlans`). The check
lives in one method so the swap is a one-line change.

### D4 — Follow repo conventions over spec snippets
Where the PDF's C# sketches differ from the repository, the repository wins (spec §90 says so), except
for the spec's non-negotiables (tool allow-list, confirmation flow, ownership, entitlements, usage
reservation, AI logging, unsupported tracking, persisted calendar, idempotency, webhook authority,
redaction). Concretely:
- Service methods take `(request, long userId)` and **no CancellationToken** (matches all existing
  services). Exception: `FitMate.Integrations` provider interfaces DO take CancellationToken (network
  calls, spec §6).
- Controllers extend `BaseApiController(ILogger<BaseApiController>, AppDbContext, IUserService)`,
  return `this.ReturnJson(...)` / `this.ReturnJsonError(...)` (`CommonJsonModel<T>` envelope).
- DTOs live in `FitMate.Core/JsonModels/<Feature>/` — they are exported to `client/src/types/backend.ts`
  by Reinforced.Typings during `dotnet build` of FitMate.Web, then `npm run process-types` in `client/`.
  **Never write TS interfaces by hand in service files** (global rule).
- Entities inherit `BaseEntity` (`Id: long`, `DateCreated`, `DateModified`) in `FitMate.DB/Entities`,
  enums in `FitMate.DB/Enums`, per-entity `IEntityTypeConfiguration` classes in `FitMate.DB/Configurations`,
  DbSets as expression-bodied properties in `AppDbContext`.
- DI: `builder.Services.AddScoped<I, Impl>()` block in `Program.cs` (~line 250–263).
- Tests: xUnit in `FitMate.Tests/Unit/Services/*Tests.cs` using `SqliteTestDatabase` (in-memory Sqlite,
  seeded `UserId=1`, `OtherUserId=2`, `AdminUserId=3`, muscle groups Chest/Back/Legs). Integration tests
  use `TestWebApplicationFactory`.

### D5 — AI proposals are 3-step, not composite
First version follows spec §31 recommended flow: AI proposes exercises → user confirms → AI proposes
templates → user confirms → AI proposes program plan → user confirms. No composite AiAction.

### D6 — Provider neutrality
Nothing outside `server/FitMate.Integrations` may reference OpenAI or Stripe SDK types. Services and
controllers consume only the `IAiCompletionProvider` / `IAiImageProvider` / `IBillingProvider`
abstractions and their neutral models.

`Plan`, `PlanPrice`, `PlanEntitlement`, `BillingCustomer`, `UserSubscription`, `BillingWebhookEvent`,
`UsageBucket`, `UsageEntry`, `UsageReservation`, `UserPlanOverride`.

**Enums (FitMate.DB/Enums):** `TrainingGoal`, `TrainingExperienceLevel`, `ProgramPlanStatus`,
`ProgramScheduleType`, `ProgramPlanDayType`, `ProgramPlanDayStatus`, `ExerciseEquipment`,
`ExerciseMovementPattern`, `ExerciseDifficulty`, `ExerciseCategory`, `AiConversationStatus`,
`AiMessageRole`, `AiRunStatus`, `AiToolExecutionStatus`, `AiActionType`, `AiActionStatus`,
`UnsupportedRequestStatus`, `AiGeneratedAssetType`, `AiJobType`, `AiJobStatus`, `SubscriptionFeature`,
`SubscriptionStatus`, `BillingInterval`, `UsageEntryType`, `UsageReservationStatus`,
`BillingWebhookStatus` — member values exactly as printed in the spec PDF (§7, §18–20, §38–46).

**Service interfaces (FitMate.Services):**
- `IProgramPlanService`, `IProgramPlanScheduleService`, `IProgramPlanDayService` (Plan 01 defines signatures)
- `IEntitlementService.RequireFeatureAsync(long userId, SubscriptionFeature feature)` /
  `GetAvailabilityAsync(...)` / `GetAllAsync(long userId)`;
  `IUsageService.ReserveAsync(long userId, SubscriptionFeature feature, int quantity)` /
  `CommitAsync(long reservationId)` / `ReleaseAsync(long reservationId)` (Plan 04)
- `ITrainingSnapshotService.BuildAsync(long userId, TrainingSnapshotOptions options)` (Plan 05)
- `IAiToolHandler` (`Name`, `Definition`, `IsAvailable(AiToolContext)`, `ExecuteAsync(argumentsJson, AiToolContext, CancellationToken)`) and
  `IAiActionExecutor` (`ActionType`, `ExecuteAsync(AiAction, long userId, CancellationToken)`) (Plans 05/06)
- `IAiRedactionService.RedactText(string)` / `RedactJson(string)` (Plan 05)

**Tool names (AI allow-list):** `get_training_profile`, `get_training_snapshot`, `get_recent_workouts`,
`get_exercise_history`, `search_exercises`, `get_workout_templates`, `get_active_program`,
`get_program_calendar`, `get_subscription_usage`, `propose_exercise`, `propose_workout`,
`propose_workout_template`, `propose_program_plan`, `propose_program_update`, `propose_exercise_image`,
`report_unsupported_request`.

**Route prefixes:** `api/program-plans`, `api/program-plan-days`, `api/ai`, `api/ai/conversations`,
`api/ai/actions`, `api/billing`, `api/admin/ai`, `api/admin/subscription-plans`. Kebab-case, `[Authorize]`
by default, admin controllers require the existing admin authorization used by `Controllers/Admin`.

**Error envelope:** limit errors use spec §49 shape (`code: "subscription_limit_reached"`, feature,
limit, used, reserved, resetsAt, upgradeAvailable) with HTTP 403 (feature not in plan) / 429 (quota
exhausted).
